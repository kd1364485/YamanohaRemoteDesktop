# 画面から画面までの遅延の測り方

PC の画面に出したミリ秒の時計と、Yamanoha で Pixel 9 に配信された同じ時計を、別のカメラで同じコマに撮ります。
2 つの時計の差が、「PC の画面が変わってから、スマホの画面に出るまで」の時間です(キャプチャ、エンコード、送信、受信側のバッファ、デコード、表示をすべて含みます)。

| ファイル | 役割 |
|---|---|
| `clock.html` | PC に出すミリ秒の時計 |
| `start-local.ps1` | ホストアプリを、ローカルのサーバーにつなぐ設定で起動 |
| `extract_frames.sh` | 撮った動画から、読み取り用のコマを取り出す |
| `calc.py` | 読み取った値から、中央値(p50)、p90、最大を出す |

## 1. 準備

1. シグナリングサーバーを起動します(`C:\Users\user\tools\yamanoha\start-signaling.ps1`)。
2. ホストアプリを起動します。`src/types.ts` を書き換える必要はありません。
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\latency\start-local.ps1
   ```
3. PC のブラウザで `http://localhost:1420/tools/latency/clock.html` を開き、クリックして全画面にします。
   下の小さな文字に出る「画面の更新: ○○ Hz」を控えておきます(数字が変わる間隔で、読み取りの細かさの限界の 1 つです)。
4. Pixel 9 で `http://<PC の IP>:1420` を開いてログインし、PC に接続して、PC で「許可する」を押します。
   Pixel 9 は**横向き**にすると、時計が大きく映って読みやすくなります。
5. 通知を切ります(PC は集中モード、Pixel 9 はサイレント)。

## 2. 撮影

1. 撮影用のスマホを、**60 fps**(できればスローモーション 120 / 240 fps)に設定します。
2. PC の画面と Pixel 9 の画面が両方とも、数字が読める大きさで同じ画面に入るように構えます。
   近いほうがよいですが、反射に注意します。三脚か、机に固定すると安定します。
3. 10〜15 秒撮ります。条件(PC の IP、Wi-Fi、Pixel の向き)を変えたら、別の動画として撮ります。

## 3. 読み取り

1. コマを取り出します(Git Bash):
   ```bash
   bash tools/latency/extract_frames.sh <動画のパス> 2 30 0.3
   ```
   2 秒目から 0.3 秒おきに 30 コマを、`<動画名>_frames/` に PNG で書き出します。
2. 各コマで、PC の時計と Pixel 9 の時計を読み、CSV に書きます。
   数字がブレて読めないときは、下の箱(100 ms の位、10 ms の位)で確かめます。それでも読めないコマは空欄にします(集計から外れます)。
   ```csv
   frame,pc,phone
   01,12.345,12.198
   02,12.648,
   ```
3. 集計します:
   ```bash
   python tools/latency/calc.py results.csv
   ```

## 読み取りの細かさ(誤差)

1 つの値には、次のずれが重なります。結果は「おおよそ ±1〜2 コマ」と考えます。

- **撮影のコマ**: 60 fps なら 1 コマ約 16.7 ms。2 つの時計は同じコマに入っているので、撮影の時刻のずれはありませんが、露光中に数字が変わると二重に写ります。
- **PC の画面の更新**: 60 Hz なら、時計の数字は約 16.7 ms ごとにしか変わりません。
- **Pixel 9 の画面の更新**: 60 Hz または 120 Hz。
- **配信の間隔**: 今のホストは約 30 fps(`docs/performance.md` のタイマーの件)なので、PC の画面が変わってから次に取り込まれるまで、最大で約 33 ms 待ちます。これは誤差ではなく遅延の一部です。

## 結果を読むときに気にすること

- 受信側(ブラウザ)は、ジッターバッファの目標を 120 ms にしています(`src/types.ts` の `JITTER_BUFFER_TARGET_MS`)。測った遅延の多くを、ここが占める可能性があります。
- ホスト側だけの時間(取り込み〜エンコード)は、`docs/performance.md` の測定で p50 約 7 ms です。画面から画面までの値との差が、送信、受信側のバッファ、デコード、表示の時間です。
